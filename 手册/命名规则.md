# Java 命名规则（EMS 项目版）

> 讲的是**写代码时**给类、方法、变量、常量、包、数据库字段起名字的规则，
> 不是手册文件的命名。规则以 Java 官方惯例（Sun/Oracle Code Conventions）为基础，
> 结合本项目 `com.github.rayman717` 的实际代码给出建议。

## 1. 总原则

好名字只需要回答三个问题：**是什么、干什么、为什么**。

| 原则 | 说明 | 好 | 差 |
| --- | --- | --- | --- |
| 见名知意 | 名字表达「是什么」，不是「怎么实现」 | `tempList` | `data`、`list1` |
| 用英文 | 拼音只有团队都懂才用，且最好不要 | `userName` | `yonghuMing` |
| 长度合理 | 作用域越大，名字越完整 | 成员变量 `connection` | 成员变量 `c` |
| 一词一义 | 同一个概念只用一个词 | 统一用 `user` | `user`、`account`、`member` 混用 |
| 风格统一 | 骆驼峰就全骆驼峰 | `userName` | `user_name` 和 `userName` 混用 |
| 不用泛名 | `data`、`info`、`obj`、`tmp` 没有信息量 | `emsRecord` | `data2` |

命名是代码里最便宜、收益最高的「注释」。写代码时多花 10 秒想名字，后面能省掉无数困惑。

## 2. 包名

规则：**全小写，域名倒置，按职责分层**。

```java
package com.github.rayman717;              // 根包
package com.github.rayman717.entity;       // 实体
package com.github.rayman717.util;         // 工具
package com.github.rayman717.view;         // 界面
package com.github.rayman717.service;      // 业务
package com.github.rayman717.dao;          // 数据访问
package com.github.rayman717.net;          // 网络
package com.github.rayman717.io;           // 文件
package com.github.rayman717.concurrent;   // 并发
```

要避免：

- 大写字母：`com.github.rayman717.View`；
- 下划线：`com.github.rayman717.my_util`；
- 缩写堆叠：`com.github.rayman717.emsmgr`。

本项目的包已经符合规则，新增模块按职责建子包即可，不要把所有类都塞进根包。

## 3. 类名与接口名

### 3.1 基本规则

- 大驼峰（UpperCamelCase）；
- 名词或名词短语，不用动词：`EmsDataServer` 好，`HandleData` 差；
- 不用 `Test`、`Utils`、`Manager` 当代号用，除非它真的是那个角色。

```java
public class DbConfig { }          // 实体
public class ConfigManager { }     // 管理类
public class SqlUtil { }           // 工具类
public class EmsMonitorFrame { }   // 窗口
public class MyDialog { }          // 对话框（Swing 手册里的例子）
```

### 3.2 后缀约定

| 后缀 | 含义 | 例子 |
| --- | --- | --- |
| `XxxFrame` / `XxxDialog` / `XxxPanel` | Swing 窗口 / 对话框 / 面板 | `EmsMonitorFrame` |
| `XxxService` | 业务逻辑 | `EmsDataService` |
| `XxxDao` / `XxxRepository` | 数据访问 | `EmsRecordDao` |
| `XxxUtil` / `XxxUtils` | 静态工具 | `SqlUtil`、`LogUtil` |
| `XxxManager` | 管理器（配置、连接） | `ConfigManager` |
| `XxxException` | 自定义异常 | `DbException` |
| `XxxConfig` | 配置实体 | `DbConfig` |
| `XxxListener` / `XxxAdapter` | 事件监听 | `RefreshListener` |
| `XxxTask` / `XxxWorker` | 并发任务 | `ExportTask` |

### 3.3 接口

接口名用形容词或名词，**不加 `I` 前缀**：

```java
public interface DataSink { void write(String line); }        // 好
public interface IDataSink { }                                 // 差（C# 风格，Java 不用）
public interface Runnable { }                                  // JDK 风格
```

抽象类用 `AbstractXxx` 或 `BaseXxx`。

## 4. 方法名

规则：**小驼峰（lowerCamelCase），动词开头，动词 + 宾语**。

| 动作 | 用词 | 例子 |
| --- | --- | --- |
| 取属性 | `getXxx` | `getName()` |
| 设属性 | `setXxx` | `setTemp()` |
| 判断 | `isXxx` / `hasXxx` / `canXxx` | `isValid()` |
| 查询数据 | `queryXxx` / `findXxx` / `loadXxx` / `fetchXxx` | `loadRecords()` |
| 保存 | `saveXxx` / `insertXxx` / `updateXxx` | `saveRecord()` |
| 删除 | `deleteXxx` / `removeXxx` / `clearXxx` | `removeRow()` |
| 创建 | `createXxx` / `buildXxx` / `initXxx` | `createTable()` |
| 转换 | `toXxx` / `asXxx` / `parseXxx` / `formatXxx` | `toCsv()` |
| 校验 | `validateXxx` / `checkXxx` | `validateInput()` |
| 执行 | `executeXxx` / `runXxx` / `startXxx` / `stopXxx` | `executeBatch()` |
| 处理 | `handleXxx` / `processXxx` | `handleRecord()` |

要避免：

| 反例 | 问题 | 改法 |
| --- | --- | --- |
| `CreateTable()` | 方法名大写开头 | `createTable()` |
| `getUserInfoData()` | 冗余堆砌 | `loadUser()` |
| `doIt()` | 看不出干什么 | `saveRecord()` |
| `isNotValid()` | 否定 + 否定，读着绕 | `isInvalid()` |
| `calculateAndSaveAndNotify()` | 一个方法干三件事 | 拆成三个方法 |

### 4.1 有副作用的方法不要用 get

`getXxx` 通常暗示「只取值、不改变状态」。如果方法里查了数据库、写了文件，用更明确的动词：

```java
public List<EmsRecord> getRecords();        // 只是取字段，可以
public List<EmsRecord> loadRecords();       // 查库，用 load 更准确
```

## 5. 变量名

### 5.1 基本规则

- 小驼峰；
- 名词，不用动词；
- 集合用复数或带类型后缀：`rows`、`recordList`、`userMap`；
- 布尔用 `is` / `has` / `can` 开头；
- 循环下标用 `i`、`j`、`k`；数组下标用 `index`；
- 成员变量**不加** `m_`、`s_` 前缀（Java 惯例，与 C++/Android 不同）。

```java
// 好
int retryCount = 3;
double avgTemperature = 26.4;
List<EmsRecord> pendingRecords = new ArrayList<>();
Map<String, Double> lastTempByDevice = new HashMap<>();
boolean autoRefreshEnabled = true;

// 差
int n = 3;
double t = 26.4;
List data = new ArrayList();
Map map1 = new HashMap();
boolean flag = true;
```

### 5.2 长度与作用域

| 作用域 | 建议长度 | 例子 |
| --- | --- | --- |
| 循环内、几行内 | 短可以接受 | `i`、`tmp` |
| 方法参数 | 完整单词 | `record`、`timeout` |
| 成员变量 | 尽量完整 | `connection`、`config` |
| 公开常量 | 完整且大写 | `TEMP_ALARM_THRESHOLD` |

「`tmp` 只允许活在三行以内」，超过就要改名。

### 5.3 别用类型名当变量名

```java
List<String> list;          // 差：叫 list 的可能是任何东西
List<String> lines;         // 好：一看就是行文本
Map<String, Integer> map;   // 差
Map<String, Integer> countByDevice;   // 好
```

## 6. 常量名

规则：`static final` + 全大写 + 下划线分隔。

```java
public static final int DEFAULT_PORT = 3306;
public static final double TEMP_ALARM_THRESHOLD = 30.0;
public static final String DEFAULT_DB_NAME = "EMS";
```

### 6.1 消除魔法值

```java
// 差：30 和 8888 是什么？
if (temp > 30) { ... }
new ServerSocket(8888);

// 好
if (temp > TEMP_ALARM_THRESHOLD) { ... }
new ServerSocket(DEFAULT_SERVER_PORT);
```

### 6.2 常量类

```java
public final class EmsConstants {
    public static final int DEFAULT_PORT = 8888;
    public static final int REFRESH_INTERVAL_MS = 5000;

    private EmsConstants() {          // 禁止实例化
    }
}
```

常量类用 `final class` + 私有构造，防止被继承和 new。

### 6.3 用枚举代替字符串常量

```java
// 差：拼错也不报错
String status = "online";
if ("onlnie".equals(status)) { ... }

// 好：编译器帮你检查
public enum DeviceStatus {
    ONLINE, OFFLINE, UNKNOWN
}
```

## 7. 枚举与泛型

```java
public enum DeviceStatus {
    ONLINE("在线"),
    OFFLINE("离线"),
    UNKNOWN("未知");

    private final String label;

    DeviceStatus(String label) {
        this.label = label;
    }

    public String getLabel() {
        return label;
    }
}
```

规则：

- 枚举类名大驼峰；
- 枚举值全大写（和常量一致）；
- 需要中文描述时放字段，不要把中文当枚举名。

泛型参数用单个大写字母：

| 参数 | 含义 |
| --- | --- |
| `T` | Type（任意类型） |
| `E` | Element（集合元素） |
| `K` / `V` | Key / Value |
| `R` | Result（返回值） |

多个泛型参数用 `T1`、`T2`，或用有意义的名字（如 `Request`、`Response`）。

## 8. 布尔值的命名

- 用**正面**语义：`isEnabled`，不要 `isNotDisabled`；
- getter 用 `isXxx()`（JavaBean 规范）；
- 别用 `flag`、`status`（含义不明）。

```java
boolean connected = true;
boolean hasPermission = false;
boolean canRetry = true;

public boolean isConnected() { return connected; }
```

双重否定是重灾区：`if (!isNotConnected)` 读起来要想两遍。

## 9. 缩写与专有名词

规则：缩写在类名里当作一个单词首字母大写、其余小写（JDK 风格）；在常量/枚举里全大写。

| 场景 | 写法 | 说明 |
| --- | --- | --- |
| 类名 | `SqlUtil`、`JsonParser`、`HttpClient` | 不是 `SQLUtil`、`JSONParser` |
| 常量 | `SQL_TIMEOUT`、`JSON_FORMAT` | 全大写没问题 |
| 变量 | `dbName`、`sqlText` | 不加多余大写 |
| 数据库 | `ems`、`user` | 表名小写 |

常见缩写保留原样：

```
ID、URL、URI、HTTP、HTTPS、TCP、UDP、IP、JSON、CSV、SQL、JDBC、HTML、XML、API、DTO、DAO、UI、GUI
```

也注意：

- `ID` 在变量里一般写 `id`（`userId` 而不是 `userID`）；
- 公司/项目名按官方写法：`EMS`、`MySQL`，不要写 `Mysql`、`EmS`。

## 10. 文件与类的对应

- 一个 `.java` 文件里最多一个 `public` 类；
- 文件名必须与 `public` 类名一致（区分大小写）；
- 非 public 类可以放在同一个文件里，但只放强相关的（比如 `MyDialog` 和 `SwingJFrame` 一起）。

```java
// 文件名：EmsMonitorFrame.java
public class EmsMonitorFrame extends JFrame { }

// 文件名：SwingJFrame.java（而不是 SwingJFream.java）
public class SwingJFrame extends JFrame { }

class MyDialog extends JDialog { }    // 同文件里的非 public 类，可以
```

文件重命名的正确方式（Git 里保留历史）：

```bash
git mv src/com/github/rayman717/view/SwingJFream.java \
       src/com/github/rayman717/view/SwingJFrame.java
```

## 11. 数据库与实体命名

### 11.1 数据库

| 对象 | 规则 | 例子 |
| --- | --- | --- |
| 表名 | 小写、下划线分隔、可加前缀 | `ems`、`user`、`sys_user` |
| 列名 | 小写下划线 | `temp`、`humidity`、`create_time` |
| 主键 | `id` | `id` |
| 外键 | `xxx_id` | `device_id` |
| 索引 | `idx_表_列` | `idx_ems_time` |

本项目的表列名现状：

```
ems : id, ALI, Temp, Humidity, Time
user: id, User, Password
```

`ALI`、`Temp`、`User` 这种「首字母大写 / 全大写」混用，在不同数据库和系统上容易踩坑（Linux 上表名区分大小写，MySQL 列名不区分但可读性差）。**建议新表统一小写下划线**：`ali`、`temp`、`humidity`、`create_time`。老表不改也能跑，但新表别学。

### 11.2 Java 实体

```java
public class DbConfig {
    private String ip;
    private String port;
    private String dbName;
    private String user;
    private String password;
    // getter / setter
}
```

字段用**小驼峰**，与数据库列名做映射：

| 数据库 | Java |
| --- | --- |
| `create_time` | `createTime` |
| `device_id` | `deviceId` |
| `humidity` | `humidity` |

如果不用 ORM，手写 `rs.getString("create_time")` 时就按数据库列名写，映射到局部变量再用小驼峰。

Swing 里组件一多，用前缀区分类型，阅读代码时一眼知道是什么控件：

| 前缀 | 组件 | 例子 |
| --- | --- | --- |
| `btn` | `JButton` | `btnRefresh` |
| `lbl` | `JLabel` | `lblStatus` |
| `txt` | `JTextField` | `txtTemp` |
| `pwd` | `JPasswordField` | `pwdLogin` |
| `chk` | `JCheckBox` | `chkAutoRefresh` |
| `rdo` | `JRadioButton` | `rdoByDay` |
| `cmb` | `JComboBox` | `cmbRange` |
| `lst` | `JList` | `lstDevices` |
| `tbl` | `JTable` | `tblRecords` |
| `scr` | `JScrollPane` | `scrTable` |
| `pnl` | `JPanel` | `pnlToolbar` |
| `frm` | `JFrame` | `frmMain` |
| `dlg` | `JDialog` | `dlgAddRecord` |
| `mnu` / `mni` | `JMenu` / `JMenuItem` | `mnuFile`、`mniExit` |
| `bar` | `JToolBar` | `barMain` |



## 13. 本项目代码对照

下面都是**建议**，不是错误；其中一部分已在后续代码里改掉了。

| 位置 | 现状 | 建议 | 原因 |
| --- | --- | --- | --- |
| `SqlUtil.CreateTable` | 方法名大写开头 | `createTable` | 方法必须小驼峰 |
| `MysqlMain` | 类名 | `MySQLMain` 或 `EmsMain` | 官方写法是 MySQL |
| `SwingJFream` | 拼写错 | `SwingJFrame` | Frame 拼写，已改名 |
| `MysqlMain` 里 `SqlUtil c = ...` | 变量 `c` | `sqlUtil` | 成员/局部变量要有意义 |
| `SqlUtil` 的 `con` 字段 | `public Connection con` | `connection` + private | 缩写过短，且应封装 |
| `ConfigManager.prop` | `private static Properties` | 可保留，或 `properties` | 静态可变状态注意线程安全 |
| `ems` 列 `ALI`、`Temp`、`Time` | 大小写混用 | 新表用 `ali`、`temp`、`create_time` | 统一风格，跨库更稳 |
| `user` 表名 | 与 MySQL 用户表同名概念 | 新项目可用 `sys_user` | 避免歧义，不是错误 |
| `LogUtil.info/error` | 静态方法 | 保持 | 语义清晰，命名良好 |
| `DbConfig` 的 public 字段 | 直接暴露 | 加 getter/setter | 封装问题（非命名） |

## 14. 反例速查表

| 反例 | 问题 | 改法 |
| --- | --- | --- |
| `int a;` / `String s;` | 无含义 | `retryCount` / `userName` |
| `List list;` / `Map map;` | 类型当名字 | `records` / `countByDevice` |
| `temp1`、`temp2`、`temp3` | 编号毫无信息 | 按用途拆名 |
| `data`、`info`、`obj` | 泛名 | 具体名词 |
| `flag` | 不知道代表什么 | `connected`、`finished` |
| `yonghu`、`wendu` | 拼音 | `user`、`temperature` |
| `getData1()` | 数字后缀 | `loadRecords()` |
| `isNotValid()` | 双重否定 | `isInvalid()` |
| `IUserService` | `I` 前缀 | `UserService` |
| `SQLUtil`、`JSONParser` | 缩写全大写 | `SqlUtil`、`JsonParser` |
| `m_count`、`s_instance` | C++ 风格前缀 | `count`、`instance` |
| `class Utils2` | 版本号进名字 | 拆成具体工具类 |
| `CreateTable()` | 方法大写 | `createTable()` |
| `handler` 当数据处理 | 语义模糊 | `handleRecord()` |
| `user_name`（Java 里） | 下划线风格 | `userName` |

## 15. 提交前检查清单

- ☐ 类名：大驼峰、名词、后缀能看出角色
- ☐ 接口名：无 `I` 前缀
- ☐ 方法名：小驼峰、动词开头
- ☐ 变量名：有意义，集合用复数
- ☐ 布尔：`is` / `has` / `can` 开头，正面语义
- ☐ 常量：`static final` + 全大写，魔法值已提取
- ☐ 枚举值：全大写
- ☐ 缩写：`Sql`、`Json`、`Http` 这种写法，不乱用全大写
- ☐ 文件名 = public 类名
- ☐ 包名全小写、按职责分层
- ☐ 数据库新表：小写下划线
- ☐ Swing 组件：`btn` / `lbl` / `txt` / `tbl` 前缀
- ☐ 没有拼音、没有 `tmp`/`data`/`flag`
- ☐ 同一概念全项目同一个词

命名规则的价值在于**一致**：团队里两个人写出的代码像一个人写的，才算规则落地。
