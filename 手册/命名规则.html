Java 命名规则（EMS 项目版）

讲的是写代码时给类、方法、变量、常量、包、数据库字段起名字的规则，不是手册文件的命名。规则以 Java 官方惯例（Sun/Oracle Code Conventions）为基础，结合本项目 com.github.rayman717 的实际代码给出建议。

1. 总原则

好名字只需要回答三个问题：是什么、干什么、为什么。

原则说明好差
见名知意名字表达「是什么」，不是「怎么实现」tempListdata、list1
用英文拼音只有团队都懂才用，且最好不要userNameyonghuMing
长度合理作用域越大，名字越完整成员变量 connection成员变量 c
一词一义同一个概念只用一个词统一用 useruser、account、member 混用
风格统一骆驼峰就全骆驼峰userNameuser_name 和 userName 混用
不用泛名data、info、obj、tmp 没有信息量emsRecorddata2

命名是代码里最便宜、收益最高的「注释」。写代码时多花 10 秒想名字，后面能省掉无数困惑。

2. 包名

规则：全小写，域名倒置，按职责分层。

package com.github.rayman717;              // 根包
package com.github.rayman717.entity;       // 实体
package com.github.rayman717.util;         // 工具
package com.github.rayman717.view;         // 界面
package com.github.rayman717.service;      // 业务
package com.github.rayman717.dao;          // 数据访问
package com.github.rayman717.net;          // 网络
package com.github.rayman717.io;           // 文件
package com.github.rayman717.concurrent;   // 并发

要避免：

  • 大写字母：com.github.rayman717.View；
  • 下划线：com.github.rayman717.my_util；
  • 缩写堆叠：com.github.rayman717.emsmgr。

本项目的包已经符合规则，新增模块按职责建子包即可，不要把所有类都塞进根包。

3. 类名与接口名

3.1 基本规则

  • 大驼峰（UpperCamelCase）；
  • 名词或名词短语，不用动词：EmsDataServer 好，HandleData 差；
  • 不用 Test、Utils、Manager 当代号用，除非它真的是那个角色。
public class DbConfig { }          // 实体
public class ConfigManager { }     // 管理类
public class SqlUtil { }           // 工具类
public class EmsMonitorFrame { }   // 窗口
public class MyDialog { }          // 对话框（Swing 手册里的例子）

3.2 后缀约定

后缀含义例子
XxxFrame / XxxDialog / XxxPanelSwing 窗口 / 对话框 / 面板EmsMonitorFrame
XxxService业务逻辑EmsDataService
XxxDao / XxxRepository数据访问EmsRecordDao
XxxUtil / XxxUtils静态工具SqlUtil、LogUtil
XxxManager管理器（配置、连接）ConfigManager
XxxException自定义异常DbException
XxxConfig配置实体DbConfig
XxxListener / XxxAdapter事件监听RefreshListener
XxxTask / XxxWorker并发任务ExportTask

3.3 接口

接口名用形容词或名词，不加 I 前缀：

public interface DataSink { void write(String line); }        // 好
public interface IDataSink { }                                 // 差（C# 风格，Java 不用）
public interface Runnable { }                                  // JDK 风格

抽象类用 AbstractXxx 或 BaseXxx。

4. 方法名

规则：小驼峰（lowerCamelCase），动词开头，动词 + 宾语。

动作用词例子
取属性getXxxgetName()
设属性setXxxsetTemp()
判断isXxx / hasXxx / canXxxisValid()
查询数据queryXxx / findXxx / loadXxx / fetchXxxloadRecords()
保存saveXxx / insertXxx / updateXxxsaveRecord()
删除deleteXxx / removeXxx / clearXxxremoveRow()
创建createXxx / buildXxx / initXxxcreateTable()
转换toXxx / asXxx / parseXxx / formatXxxtoCsv()
校验validateXxx / checkXxxvalidateInput()
执行executeXxx / runXxx / startXxx / stopXxxexecuteBatch()
处理handleXxx / processXxxhandleRecord()

要避免：

反例问题改法
CreateTable()方法名大写开头createTable()
getUserInfoData()冗余堆砌loadUser()
doIt()看不出干什么saveRecord()
isNotValid()否定 + 否定，读着绕isInvalid()
calculateAndSaveAndNotify()一个方法干三件事拆成三个方法

4.1 有副作用的方法不要用 get

getXxx 通常暗示「只取值、不改变状态」。如果方法里查了数据库、写了文件，用更明确的动词：

public List<EmsRecord> getRecords();        // 只是取字段，可以
public List<EmsRecord> loadRecords();       // 查库，用 load 更准确

5. 变量名

5.1 基本规则

  • 小驼峰；
  • 名词，不用动词；
  • 集合用复数或带类型后缀：rows、recordList、userMap；
  • 布尔用 is / has / can 开头；
  • 循环下标用 i、j、k；数组下标用 index；
  • 成员变量不加 m_、s_ 前缀（Java 惯例，与 C++/Android 不同）。
// 好
int retryCount = 3;
double avgTemperature = 26.4;
List<EmsRecord> pendingRecords = new ArrayList<>();
Map<String, Double> lastTempByDevice = new HashMap<>();
boolean autoRefreshEnabled = true;

// 差
int n = 3;
double t = 26.4;
List data = new ArrayList();
Map map1 = new HashMap();
boolean flag = true;

5.2 长度与作用域

作用域建议长度例子
循环内、几行内短可以接受i、tmp
方法参数完整单词record、timeout
成员变量尽量完整connection、config
公开常量完整且大写TEMP_ALARM_THRESHOLD

「tmp 只允许活在三行以内」，超过就要改名。

5.3 别用类型名当变量名

List<String> list;          // 差：叫 list 的可能是任何东西
List<String> lines;         // 好：一看就是行文本
Map<String, Integer> map;   // 差
Map<String, Integer> countByDevice;   // 好

6. 常量名

规则：static final + 全大写 + 下划线分隔。

public static final int DEFAULT_PORT = 3306;
public static final double TEMP_ALARM_THRESHOLD = 30.0;
public static final String DEFAULT_DB_NAME = "EMS";

6.1 消除魔法值

// 差：30 和 8888 是什么？
if (temp > 30) { ... }
new ServerSocket(8888);

// 好
if (temp > TEMP_ALARM_THRESHOLD) { ... }
new ServerSocket(DEFAULT_SERVER_PORT);

6.2 常量类

public final class EmsConstants {
    public static final int DEFAULT_PORT = 8888;
    public static final int REFRESH_INTERVAL_MS = 5000;

    private EmsConstants() {          // 禁止实例化
    }
}

常量类用 final class + 私有构造，防止被继承和 new。

6.3 用枚举代替字符串常量

// 差：拼错也不报错
String status = "online";
if ("onlnie".equals(status)) { ... }

// 好：编译器帮你检查
public enum DeviceStatus {
    ONLINE, OFFLINE, UNKNOWN
}

7. 枚举与泛型

public enum DeviceStatus {
    ONLINE("在线"),
    OFFLINE("离线"),
    UNKNOWN("未知");

    private final String label;

    DeviceStatus(String label) {
        this.label = label;
    }

    public String getLabel() {
        return label;
    }
}

规则：

  • 枚举类名大驼峰；
  • 枚举值全大写（和常量一致）；
  • 需要中文描述时放字段，不要把中文当枚举名。

泛型参数用单个大写字母：

参数含义
TType（任意类型）
EElement（集合元素）
K / VKey / Value
RResult（返回值）

多个泛型参数用 T1、T2，或用有意义的名字（如 Request、Response）。

8. 布尔值的命名

  • 用正面语义：isEnabled，不要 isNotDisabled；
  • getter 用 isXxx()（JavaBean 规范）；
  • 别用 flag、status（含义不明）。
boolean connected = true;
boolean hasPermission = false;
boolean canRetry = true;

public boolean isConnected() { return connected; }

双重否定是重灾区：if (!isNotConnected) 读起来要想两遍。

9. 缩写与专有名词

规则：缩写在类名里当作一个单词首字母大写、其余小写（JDK 风格）；在常量/枚举里全大写。

场景写法说明
类名SqlUtil、JsonParser、HttpClient不是 SQLUtil、JSONParser
常量SQL_TIMEOUT、JSON_FORMAT全大写没问题
变量dbName、sqlText不加多余大写
数据库ems、user表名小写

常见缩写保留原样：

ID、URL、URI、HTTP、HTTPS、TCP、UDP、IP、JSON、CSV、SQL、JDBC、HTML、XML、API、DTO、DAO、UI、GUI

也注意：

  • ID 在变量里一般写 id（userId 而不是 userID）；
  • 公司/项目名按官方写法：EMS、MySQL，不要写 Mysql、EmS。

10. 文件与类的对应

  • 一个 .java 文件里最多一个 public 类；
  • 文件名必须与 public 类名一致（区分大小写）；
  • 非 public 类可以放在同一个文件里，但只放强相关的（比如 MyDialog 和 SwingJFrame 一起）。
// 文件名：EmsMonitorFrame.java
public class EmsMonitorFrame extends JFrame { }

// 文件名：SwingJFrame.java（而不是 SwingJFream.java）
public class SwingJFrame extends JFrame { }

class MyDialog extends JDialog { }    // 同文件里的非 public 类，可以

文件重命名的正确方式（Git 里保留历史）：

git mv src/com/github/rayman717/view/SwingJFream.java \
       src/com/github/rayman717/view/SwingJFrame.java

11. 数据库与实体命名

11.1 数据库

对象规则例子
表名小写、下划线分隔、可加前缀ems、user、sys_user
列名小写下划线temp、humidity、create_time
主键idid
外键xxx_iddevice_id
索引idx_表_列idx_ems_time

本项目的表列名现状：

ems : id, ALI, Temp, Humidity, Time
user: id, User, Password

ALI、Temp、User 这种「首字母大写 / 全大写」混用，在不同数据库和系统上容易踩坑（Linux 上表名区分大小写，MySQL 列名不区分但可读性差）。建议新表统一小写下划线：ali、temp、humidity、create_time。老表不改也能跑，但新表别学。

11.2 Java 实体

public class DbConfig {
    private String ip;
    private String port;
    private String dbName;
    private String user;
    private String password;
    // getter / setter
}

字段用小驼峰，与数据库列名做映射：

数据库Java
create_timecreateTime
device_iddeviceId
humidityhumidity

如果不用 ORM，手写 rs.getString("create_time") 时就按数据库列名写，映射到局部变量再用小驼峰。

15. 提交前检查清单

  • ☐ 类名：大驼峰、名词、后缀能看出角色
  • ☐ 接口名：无 I 前缀
  • ☐ 方法名：小驼峰、动词开头
  • ☐ 变量名：有意义，集合用复数
  • ☐ 布尔：is / has / can 开头，正面语义
  • ☐ 常量：static final + 全大写，魔法值已提取
  • ☐ 枚举值：全大写
  • ☐ 缩写：Sql、Json、Http 这种写法，不乱用全大写
  • ☐ 文件名 = public 类名
  • ☐ 包名全小写、按职责分层
  • ☐ 数据库新表：小写下划线
  • ☐ Swing 组件：btn / lbl / txt / tbl 前缀
  • ☐ 没有拼音、没有 tmp/data/flag
  • ☐ 同一概念全项目同一个词

命名规则的价值在于一致：团队里两个人写出的代码像一个人写的，才算规则落地。
