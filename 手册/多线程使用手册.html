1. 什么时候需要多线程

场景为什么需要
服务端接收多台设备一台设备一个连接，不能让第二台排队等第一台
Swing / 桌面界面界面刷新在 EDT，查库、网络请求必须放后台，否则窗口卡死
批量导入、导出文件大文件读写耗时，放后台不耽误用户操作
定时任务每 5 分钟汇总一次数据，独立线程跑

多线程不会让单件事变快，它解决的是「同时做多件事」和「不阻塞」。

判断密集类型：

类型特征线程数建议
CPU 密集大量计算、循环CPU 核数 + 1
IO 密集等数据库、等网络、读写文件CPU 核数 × 2 或更多

网络和数据库操作属于「等」，线程多一些反而吞吐更高。

2. 创建线程的四种方式

2.1 继承 Thread

public class CountThread extends Thread {
    @Override
    public void run() {
        System.out.println("线程执行：" + getName());
    }
}

new CountThread().start();

缺点：Java 单继承，继承 Thread 就不能再继承别的类，一般不推荐。

2.2 实现 Runnable

Runnable task = () -> System.out.println("任务执行：" + Thread.currentThread().getName());
Thread t = new Thread(task, "worker-1");
t.start();

推荐这一种：任务和线程解耦，还能交给线程池执行。

2.3 实现 Callable（有返回值、能抛异常）

ExecutorService pool = Executors.newFixedThreadPool(2);

Future<Integer> future = pool.submit(() -> {
    Thread.sleep(1000);
    return 42;
});

int value = future.get();          // 阻塞等结果
System.out.println("结果：" + value);

Callable 与 Runnable 的区别：有返回值、可以抛受检异常。

2.4 用线程池（最推荐）

ExecutorService pool = Executors.newFixedThreadPool(4);
pool.submit(() -> doSomething());

四种方式对比：

方式返回值复用线程推荐度
继承 Thread无不能低
实现 Runnable无交给线程池可复用中
实现 Callable有可中
线程池 + 任务都可是高

永远不要用 new Thread(...).start() 去跑大量任务，线程创建和销毁都很贵。

3. 线程的常用操作

Thread t = new Thread(() -> {
    System.out.println("子线程开始");
    try {
        Thread.sleep(2000);                 // 睡眠 2 秒
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();  // 恢复中断标志，别吞掉
    }
    System.out.println("子线程结束");
}, "worker-1");

t.setDaemon(true);      // 守护线程：主线程结束时它也会被结束
t.start();              // 启动
t.join();               // 等它结束（阻塞当前线程）
System.out.println("主线程继续");

System.out.println(t.isAlive());        // 是否还活着
System.out.println(t.getState());       // NEW / RUNNABLE / BLOCKED / WAITING / TIMED_WAITING / TERMINATED

几个容易写错的点：

写法结果
t.run()在当前线程里同步执行，不是新线程
t.start()真正启动新线程
Thread.sleep(1000)会抛 InterruptedException，必须处理
Thread.currentThread().interrupt()捕获中断异常后恢复标志，方便上层判断
守护线程主线程结束即结束，适合后台心跳/监控

线程状态流转（简化）：

NEW → RUNNABLE → (BLOCKED / WAITING / TIMED_WAITING) → TERMINATED

4. 线程安全问题

4.1 一个必现的错误

public class Counter {
    private int count = 0;

    public void add() {
        count++;          // 不是原子操作：读 → 加 → 写
    }

    public int get() {
        return count;
    }
}

// 1000 个线程各加 1 次，结果经常小于 1000

原因：count++ 分三步执行，两个线程可能同时读到旧值再写回，后写的覆盖先写的。

4.2 根源

只有一条：多个线程共享同一个可变状态，且至少有一个线程在写。

4.3 三种解决思路

思路做法例子
不共享用局部变量、不可变对象方法内 int sum = 0
加锁synchronized、Lock累加、复合判断
用并发工具原子类、并发集合AtomicInteger、ConcurrentHashMap

EMS 里的真实例子：多台设备同时上报，如果多个线程往同一个 ArrayList 里 add，可能丢数据甚至抛 ConcurrentModificationException。要么加锁，要么换 CopyOnWriteArrayList 或 BlockingQueue。

5. synchronized 与 volatile

5.1 synchronized 的三种写法

// ① 实例方法：锁当前对象 this
public synchronized void add() {
    count++;
}

// ② 静态方法：锁这个类的 Class 对象
public static synchronized void init() {
    // ...
}

// ③ 代码块：自己指定锁对象
private final Object lock = new Object();

public void add() {
    synchronized (lock) {
        count++;
    }
}

要点：

  • 锁的是对象，同一个锁对象才互斥；
  • 可重入：同一个线程可以重复进入同一个锁；
  • 锁对象建议用 private final Object，不要用 String 常量（字符串常量池可能被别处复用）；
  • 代码块比方法粒度小，只包住真正需要互斥的部分，别把耗时的数据库操作也包进去。

5.2 可见性问题

public class StopFlag {
    private volatile boolean running = true;

    public void stop() {
        running = false;
    }

    public void loop() {
        while (running) {
            // 干活
        }
    }
}

不加 volatile 时，线程可能永远读到缓存的 true，循环停不下来。

volatile 保证「写入立刻对其他线程可见」，但它不保证原子性：

private volatile int count = 0;
count++;          // 依然不安全！volatile 只管可见，不管原子

需要原子性时用 AtomicInteger 或 synchronized。

6. 原子类

import java.util.concurrent.atomic.AtomicInteger;
import java.util.concurrent.atomic.LongAdder;

private final AtomicInteger received = new AtomicInteger();

received.incrementAndGet();          // 等价于 ++received，原子
received.getAndIncrement();          // 先取值再加
received.addAndGet(10);
received.compareAndSet(10, 20);      // 如果当前是 10 就改成 20，成功返回 true
int now = received.get();

高并发计数（只增不减、不需要立刻读取精确值）用 LongAdder 更快：

LongAdder counter = new LongAdder();
counter.increment();
long total = counter.sum();

原子类适合「单个变量的读写和计数」，多变量或复杂逻辑还是要用锁。

7. Lock 与条件变量

synchronized 够用就别换，但遇到「需要超时」「需要中断」「需要多个条件」时用 ReentrantLock。

import java.util.concurrent.locks.ReentrantLock;

private final ReentrantLock lock = new ReentrantLock();

public void add() {
    lock.lock();
    try {
        count++;
    } finally {
        lock.unlock();          // 必须在 finally 里释放
    }
}

几个 synchronized 没有的能力：

// ① 尝试加锁，拿不到不阻塞
if (lock.tryLock()) {
    try {
        // ...
    } finally {
        lock.unlock();
    }
}

// ② 限时加锁，避免死等
if (lock.tryLock(2, TimeUnit.SECONDS)) {
    try {
        // ...
    } finally {
        lock.unlock();
    }
}

// ③ 公平锁：按等待顺序获得锁（性能略低）
ReentrantLock fairLock = new ReentrantLock(true);

// ④ 可中断
lock.lockInterruptibly();

条件变量（替代 wait/notify）：

private final ReentrantLock lock = new ReentrantLock();
private final Condition notEmpty = lock.newCondition();
private final Condition notFull = lock.newCondition();
private final LinkedList<String> queue = new LinkedList<>();

public void put(String item) throws InterruptedException {
    lock.lock();
    try {
        while (queue.size() >= 100) {
            notFull.await();          // 满了就等
        }
        queue.addLast(item);
        notEmpty.signalAll();         // 通知消费者
    } finally {
        lock.unlock();
    }
}

public String take() throws InterruptedException {
    lock.lock();
    try {
        while (queue.isEmpty()) {
            notEmpty.await();         // 空了就等
        }
        String item = queue.removeFirst();
        notFull.signalAll();
        return item;
    } finally {
        lock.unlock();
    }
}

读写锁（读多写少，比如配置缓存）：

ReadWriteLock rw = new ReentrantReadWriteLock();
rw.readLock().lock();     // 多线程可同时读
rw.writeLock().lock();    // 写时独占

8. wait/notify 与生产者消费者

synchronized 配合 wait/notify 也能做生产者消费者，但要注意三个硬性要求：

  1. wait/notify 必须在 synchronized 块里调用；
  2. 必须用 while 循环判断条件（防「虚假唤醒」）；
  3. 唤醒用 notifyAll 而不是 notify（notify 可能叫错线程导致卡死）。
public class Buffer {
    private final String[] items = new String[10];
    private int count = 0;
    private int putIndex = 0;
    private int takeIndex = 0;

    public synchronized void put(String item) throws InterruptedException {
        while (count == items.length) {
            wait();                    // 满了，等消费者取
        }
        items[putIndex] = item;
        putIndex = (putIndex + 1) % items.length;
        count++;
        notifyAll();                   // 通知等待的线程
    }

    public synchronized String take() throws InterruptedException {
        while (count == 0) {
            wait();                    // 空了，等生产者放
        }
        String item = items[takeIndex];
        takeIndex = (takeIndex + 1) % items.length;
        count--;
        notifyAll();
        return item;
    }
}

实际项目里直接用 BlockingQueue，它就是把这个模式封装好了：

BlockingQueue<String> queue = new LinkedBlockingQueue<>(100);
queue.put("data");      // 满了阻塞
String item = queue.take();   // 空了阻塞

9. 并发集合与阻塞队列

9.1 常用并发集合

类特点适用
ConcurrentHashMap分段/桶级并发，读写都快共享缓存、在线设备表
CopyOnWriteArrayList写时复制，读极快、写很贵监听器列表、配置项（读多写少）
ConcurrentLinkedQueue无锁队列高并发生产者消费者
BlockingQueue 家族支持阻塞等待任务队列、数据缓冲
ConcurrentHashMap<String, Double> lastTemp = new ConcurrentHashMap<>();
lastTemp.put("device-1", 26.4);
lastTemp.computeIfAbsent("device-2", k -> 0.0);      // 不存在才放，原子
lastTemp.merge("device-1", 0.5, Double::sum);        // 原子累加

普通 HashMap 在多线程下同时 put 可能丢数据甚至死循环（JDK 8 之前），别裸用。

9.2 BlockingQueue 的四个方法

方法队列满/空时
put(e)满了阻塞等待
offer(e)满了返回 false
offer(e, timeout, unit)满了等一会儿，超时返回 false
take()空了阻塞等待
poll()空了返回 null
poll(timeout, unit)空了等一会儿，超时返回 null

EMS 场景：设备上报很猛、数据库写得慢，中间放一个有界队列缓冲，满了就拒绝（而不是把内存撑爆）。

BlockingQueue<EmsRecord> queue = new LinkedBlockingQueue<>(5000);

// 接收线程
if (!queue.offer(record)) {
    System.out.println("队列已满，丢弃一条");
}

// 写库线程
EmsRecord r = queue.take();
saveToDatabase(r);

10. 线程池

10.1 为什么用线程池

  • 线程创建/销毁开销大，复用一批线程更划算；
  • 能限制并发数量，防止线程爆炸；
  • 统一管理、监控、优雅关闭。

10.2 不要直接 new 线程

// 反例：1000 台设备就 1000 个线程，内存和调度都扛不住
while (true) {
    Socket socket = server.accept();
    new Thread(() -> handle(socket)).start();
}

10.3 Executors 的四种快捷工厂

方法线程数风险
newFixedThreadPool(n)固定 n队列无界（LinkedBlockingQueue），任务堆积可能 OOM
newCachedThreadPool()无上限（空闲 60 秒回收）线程数可能爆炸
newSingleThreadExecutor()1同样队列无界
newScheduledThreadPool(n)固定 n定时任务用

小项目用 newFixedThreadPool 就行，但要知道它的队列是无界的。

10.4 直接构造 ThreadPoolExecutor（生产推荐）

ThreadPoolExecutor pool = new ThreadPoolExecutor(
        4,                          // 核心线程数
        8,                          // 最大线程数
        60, TimeUnit.SECONDS,       // 空闲线程存活时间
        new ArrayBlockingQueue<>(1000),       // 有界队列，防止任务无限堆积
        r -> {
            Thread t = new Thread(r);
            t.setName("ems-worker-" + t.getId());
            t.setDaemon(false);
            return t;               // 给线程起名，jstack 排查时好认
        },
        new ThreadPoolExecutor.AbortPolicy()  // 满了怎么办
);

七个参数的含义：

参数作用
corePoolSize常驻线程数，任务少也不回收
maximumPoolSize最多线程数
keepAliveTime超过核心数的空闲线程存活多久
workQueue任务队列，有界还是无界很关键
threadFactory线程工厂，用来命名、设守护
handler拒绝策略
（时间单位）keepAliveTime 的单位

任务提交后的执行顺序：

核心线程未满 → 创建核心线程
核心线程已满 → 任务进队列
队列已满 → 创建非核心线程（直到 maximumPoolSize）
队列满且线程也满 → 执行拒绝策略

四种拒绝策略：

策略行为
AbortPolicy抛 RejectedExecutionException（默认）
CallerRunsPolicy让提交任务的线程自己跑，相当于限速
DiscardPolicy静默丢弃
DiscardOldestPolicy丢掉队列里最老的，再提交

设备上报这种场景，建议 CallerRunsPolicy 或自己实现「记录日志 + 丢弃」。

10.5 线程池大小估算

int cpu = Runtime.getRuntime().availableProcessors();
int poolSize = cpu * 2;      // IO 密集型（查库、网络）大致经验值

数据库查询、网络请求都是「等待」，线程可以多一些；纯计算就 cpu + 1。

10.6 优雅关闭

pool.shutdown();                              // 不再接收新任务，等已提交的跑完
if (!pool.awaitTermination(30, TimeUnit.SECONDS)) {
    pool.shutdownNow();                       // 超时强制中断
}

shutdownNow() 只是给线程发中断信号，任务要自己响应 isInterrupted() 才会真的停。

10.7 监控

System.out.println("活跃线程：" + pool.getActiveCount());
System.out.println("排队任务：" + pool.getQueue().size());
System.out.println("已完成任务：" + pool.getCompletedTaskCount());

11. CompletableFuture

适合「多个异步任务串联 / 并行后合并」的场景，比手写回调干净。

11.1 基本用法

ExecutorService pool = Executors.newFixedThreadPool(4);

CompletableFuture<Double> future = CompletableFuture.supplyAsync(() -> {
    return queryAvgTemp();          // 后台执行，有返回值
}, pool);

future.thenAccept(avg -> System.out.println("平均温度：" + avg));

11.2 串联与转换

CompletableFuture<Integer> result = CompletableFuture
        .supplyAsync(() -> loadRows(), pool)          // 查条目数
        .thenApply(n -> n * 2)                        // 转换
        .thenApply(n -> n + 1);                       // 继续处理

CompletableFuture<Void> done = result.thenAccept(n -> System.out.println(n));

thenApply 是「转换」，thenCompose 是「再返回一个新的 Future」（类似 flatMap）。

11.3 并行合并

CompletableFuture<Double> tempTask = CompletableFuture.supplyAsync(() -> avgTemp(), pool);
CompletableFuture<Double> humTask = CompletableFuture.supplyAsync(() -> avgHumidity(), pool);

CompletableFuture<Void> all = CompletableFuture.allOf(tempTask, humTask);
all.join();

System.out.println("温度：" + tempTask.join());
System.out.println("湿度：" + humTask.join());

11.4 异常处理

CompletableFuture<Double> safe = CompletableFuture
        .supplyAsync(() -> mayThrow(), pool)
        .exceptionally(ex -> {
            System.out.println("出错：" + ex.getCause());
            return 0.0;                              // 出错时的兜底值
        })
        .handle((value, ex) -> ex == null ? value : 0.0);   // 统一处理

11.5 超时（JDK 9+）

CompletableFuture<Double> f = CompletableFuture.supplyAsync(() -> slowQuery(), pool)
        .orTimeout(3, TimeUnit.SECONDS)
        .exceptionally(ex -> -1.0);

12. 线程协作工具

工具作用场景
CountDownLatch等 N 个任务都完成再继续启动时加载多个模块
CyclicBarrierN 个线程互相等，到齐了一起走分批并行计算
Semaphore限制同时访问的数量限流、连接数控制
Exchanger两个线程交换数据少见
// CountDownLatch：等 5 个设备数据都到齐，再算平均值
CountDownLatch latch = new CountDownLatch(5);
for (int i = 0; i < 5; i++) {
    pool.submit(() -> {
        try {
            fetchAndStore();
        } finally {
            latch.countDown();
        }
    });
}
latch.await();
System.out.println("5 个任务都完成了");

// Semaphore：最多 3 个线程同时查库
Semaphore semaphore = new Semaphore(3);
semaphore.acquire();
try {
    queryDatabase();
} finally {
    semaphore.release();
}

13. 死锁

13.1 典型成因

两个线程以相反顺序抢同一对锁：

// 线程 A
synchronized (lockA) {
    synchronized (lockB) { ... }
}

// 线程 B
synchronized (lockB) {
    synchronized (lockA) { ... }
}

13.2 避免方法

  • 固定加锁顺序（所有线程都先拿 A 再拿 B）；
  • 用 tryLock(timeout)，拿不到就放弃并重试；
  • 缩小锁范围，尽量不在持有锁时调用其他可能加锁的方法；
  • 不要嵌套太多锁。

13.3 诊断

jps                          # 找到 Java 进程的 pid
jstack 12345                 # 打印线程栈

如果发生死锁，jstack 输出里会有：

Found one Java-level deadlock:

然后列出两个线程分别持有什么锁、等什么锁。

14. 实战：EMS 数据接收的并发处理

需求：多台设备并发上报 → 不丢数据、不撑爆内存 → 单线程批量写库 → 支持优雅关闭。

结构：

设备连接（多个线程）
      │  offer 到有界队列
      ▼
BlockingQueue（容量 5000）
      │  take 批量取
      ▼
写库线程（单线程，批量 INSERT）
package com.github.rayman717.concurrent;

import com.github.rayman717.entity.DbConfig;
import com.github.rayman717.util.ConfigManager;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.BlockingQueue;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.atomic.AtomicLong;

/**
 * EMS 数据接收的并发处理示例。
 * <p>
 * 生产端：多个线程并发把数据放进有界队列；
 * 消费端：单线程批量写数据库，减少连接与事务开销。
 */
public class EmsIngestService {

    /** 一条上报数据 */
    public static class Record {
        final double ali;
        final double temp;
        final double humidity;

        public Record(double ali, double temp, double humidity) {
            this.ali = ali;
            this.temp = temp;
            this.humidity = humidity;
        }
    }

    private static final int QUEUE_CAPACITY = 5000;
    private static final int BATCH_SIZE = 200;

    private final BlockingQueue<Record> queue = new ArrayBlockingQueue<>(QUEUE_CAPACITY);
    private final AtomicLong accepted = new AtomicLong();
    private final AtomicLong rejected = new AtomicLong();
    private final AtomicLong saved = new AtomicLong();

    private final ExecutorService producers = Executors.newFixedThreadPool(8);
    private final ExecutorService consumer = Executors.newSingleThreadExecutor();
    private volatile boolean running = true;

    /** 启动写库线程 */
    public void start() {
        consumer.submit(this::consumeLoop);
    }

    /** 模拟一台设备上报（真实场景从 Socket 读到后调用） */
    public void submit(Record record) {
        if (!running) {
            return;
        }
        if (queue.offer(record)) {
            accepted.incrementAndGet();
        } else {
            rejected.incrementAndGet();               // 队列满：宁可丢，不撑爆内存
        }
    }

    /** 批量写库：攒够 BATCH_SIZE 或超时 1 秒就写一次 */
    private void consumeLoop() {
        List<Record> batch = new ArrayList<>(BATCH_SIZE);
        while (running || !queue.isEmpty()) {
            try {
                Record first = queue.poll(1, TimeUnit.SECONDS);
                if (first != null) {
                    batch.add(first);
                }
                queue.drainTo(batch, BATCH_SIZE - batch.size());
                if (!batch.isEmpty()) {
                    saveBatch(batch);
                    saved.addAndGet(batch.size());
                    batch.clear();
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();   // 恢复中断标志
                break;
            } catch (Exception e) {
                System.out.println("批量写库失败：" + e.getMessage());
            }
        }
    }

    private void saveBatch(List<Record> batch) throws Exception {
        DbConfig config = ConfigManager.getDbConfig();
        String url = "jdbc:mysql://" + config.ip + ":3306/" + config.dbName
                + "?useSSL=false&characterEncoding=utf8";
        String sql = "INSERT INTO ems (ALI, Temp, Humidity) VALUES (?, ?, ?)";

        try (Connection con = DriverManager.getConnection(url, config.user, config.password);
             PreparedStatement ps = con.prepareStatement(sql)) {
            for (Record r : batch) {
                ps.setDouble(1, r.ali);
                ps.setDouble(2, r.temp);
                ps.setDouble(3, r.humidity);
                ps.addBatch();
            }
            ps.executeBatch();                        // 一次网络往返写多条
        }
    }

    /** 优雅关闭：不再接收 → 等队列写完 → 关线程池 */
    public void shutdown() throws InterruptedException {
        running = false;
        consumer.shutdown();
        consumer.awaitTermination(10, TimeUnit.SECONDS);
        producers.shutdownNow();
        System.out.println("接收 " + accepted + " 条，拒绝 " + rejected + " 条，入库 " + saved + " 条");
    }
}
