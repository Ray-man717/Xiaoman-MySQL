## 1. 集合框架总览

Java 集合分两大阵营：

```
Collection（单个元素的集合）
├── List（有序、可重复、有下标）
│   ├── ArrayList      数组，查快
│   ├── LinkedList     链表，头尾增删快
│   └── Vector         老式线程安全数组（不推荐）
├── Set（不重复）
│   ├── HashSet        哈希表，无序
│   ├── LinkedHashSet  哈希 + 链表，保持插入顺序
│   └── TreeSet        红黑树，自动排序
└── Queue（队列）
    ├── ArrayDeque
    ├── PriorityQueue  优先队列
    └── BlockingQueue  阻塞队列（并发用）

Map（键值对集合）
├── HashMap            哈希表，最常用
├── LinkedHashMap      保持插入/访问顺序
├── TreeMap            按 key 排序
├── Hashtable          老式线程安全（不推荐）
└── ConcurrentHashMap  并发安全、性能好（推荐）
```

一句话选择：

| 需求 | 用什么 |
| --- | --- |
| 按顺序存一堆东西、要下标 | `ArrayList` |
| 去重 | `HashSet` |
| 键值对、按键快速查 | `HashMap` |
| 键值对、按 key 排序 | `TreeMap` |
| 键值对、保持插入顺序 | `LinkedHashMap` |
| 多线程共享 | `ConcurrentHashMap` |
| 老代码里遇到 | `Hashtable` / `Vector` |

## 2. List 家族

### 2.1 ArrayList

```java
List<String> list = new ArrayList<>();
list.add("A");
list.add("B");
list.add(0, "开头");           // 插到下标 0
list.get(0);                  // "开头"
list.set(0, "新");             // 改
list.remove("A");             // 按值删
list.remove(0);               // 按下标删
list.size();
list.contains("B");
list.indexOf("B");
list.isEmpty();
list.clear();
```

特点：底层是数组，**随机访问快，中间插入删除慢**（要移动元素）。

默认容量 10，满了扩容 **1.5 倍**。

### 2.2 LinkedList

```java
List<String> list = new LinkedList<>();
list.add("A");
list.addFirst("头");
list.addLast("尾");
```

底层是双向链表：**头尾增删快，按下标访问慢**（要一个个走）。

实际项目里 `ArrayList` 用得最多，`LinkedList` 只适合「频繁在两端增删」的场景，比如当队列用。

### 2.3 Vector（老式，不推荐）

```java
Vector<String> v = new Vector<>();
v.add("A");
```

方法都加了 `synchronized`，相当于每个操作都锁全表，性能差。新代码用 `ArrayList` + 自己控制同步，或 `CopyOnWriteArrayList`。

### 2.4 三个 List 对比

| | ArrayList | LinkedList | Vector |
| --- | --- | --- | --- |
| 底层 | 数组 | 双向链表 | 数组 |
| 随机访问 | 快 O(1) | 慢 O(n) | 快 |
| 中间插入/删除 | 慢 O(n) | 快 O(1)（有节点引用时） | 慢 |
| 线程安全 | 否 | 否 | 是（全表锁） |
| 推荐 | ★★★ | ★☆☆ | 老代码 |

## 3. Set 家族

Set 的核心特点：**不重复**。

### 3.1 HashSet

```java
Set<String> set = new HashSet<>();
set.add("A");
set.add("A");             // 加不进去，size 还是 1
set.contains("A");        // true
set.remove("A");
set.size();
```

无序：遍历顺序和添加顺序无关。

### 3.2 LinkedHashSet

```java
Set<String> set = new LinkedHashSet<>();
set.add("B");
set.add("A");
set.add("C");
// 遍历顺序：B, A, C（保持插入顺序）
```

### 3.3 TreeSet

```java
Set<Integer> set = new TreeSet<>();
set.add(3);
set.add(1);
set.add(2);
// 遍历顺序：1, 2, 3（自动排序）

set.first();       // 1
set.last();        // 3
set.headSet(2);    // [1]
set.tailSet(2);    // [2, 3]
```

### 3.4 三个 Set 对比

| | HashSet | LinkedHashSet | TreeSet |
| --- | --- | --- | --- |
| 顺序 | 无序 | 插入顺序 | 排序 |
| 底层 | HashMap | LinkedHashMap | TreeMap |
| 性能 | 最快 | 稍慢 | 慢（O(log n)） |
| 允许 null | 允许一个 | 允许一个 | 不允许（会抛异常） |

## 4. Map 家族

Map 存「键 → 值」，键不能重复。

### 4.1 五个 Map 对比

| | HashMap | LinkedHashMap | TreeMap | Hashtable | ConcurrentHashMap |
| --- | --- | --- | --- | --- | --- |
| 顺序 | 无序 | 插入/访问顺序 | key 排序 | 无序 | 无序 |
| 线程安全 | 否 | 否 | 否 | 是（全表锁） | 是（桶级） |
| null 键 | 允许 1 个 | 允许 1 个 | 不允许 | 不允许 | 不允许 |
| null 值 | 允许 | 允许 | 允许 | 不允许 | 不允许 |
| 性能 | 快 | 稍慢 | O(log n) | 慢 | 快 |
| 推荐 | ★★★ | 按需 | 按需 | 老代码 | 并发场景 |

### 4.2 基本操作（以 HashMap 为例）

```java
Map<String, Double> temp = new HashMap<>();

temp.put("ems-01", 26.4);              // 放
temp.get("ems-01");                    // 26.4
temp.get("ems-99");                    // null
temp.getOrDefault("ems-99", 0.0);      // 0.0
temp.containsKey("ems-01");            // true
temp.containsValue(26.4);              // true
temp.remove("ems-01");                 // 删
temp.size();
temp.isEmpty();
temp.keySet();                         // 所有键
temp.values();                         // 所有值
temp.entrySet();                       // 所有键值对
```

`put` 同一个 key 会覆盖旧值，并返回旧值：

```java
Double old = temp.put("ems-01", 27.0);   // old = 26.4
```

## 5. HashMap 内部原理

理解原理，才知道为什么「初始容量」和「hashCode」重要。

### 5.1 结构

```
数组（桶数组 table）
 ├── [0] → 链表/红黑树 → 节点(key, value, hash, next)
 ├── [1] → null
 ├── [2] → 节点
 ...
```

- 每个元素存在「桶」里，桶的位置由 `key.hashCode()` 计算；
- 同一个桶里的多个元素用**链表**串起来；
- JDK 8 起，链表长度 ≥ 8 且数组长度 ≥ 64 时，转成**红黑树**（查询从 O(n) 变 O(log n)）。

### 5.2 定位过程

```java
// 简化版
int hash = key.hashCode();
int index = (数组长度 - 1) & hash;   // 等价于 hash % 长度，但更快
```

- 数组长度总是 2 的幂（16、32、64…），这样 `&` 才等价于取模；
- `hash` 还会做一次扰动（高 16 位异或），减少冲突。

### 5.3 扩容

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 初始容量 | 16 | 第一次 put 时创建 |
| 负载因子 | 0.75 | 元素数 > 容量 × 0.75 就扩容 |
| 扩容 | × 2 | 重新分配并迁移元素（rehash） |

```java
// 已知要放 1000 个元素，直接给容量，避免反复扩容
Map<String, Double> map = new HashMap<>(1024);
```

计算：预期元素数 / 0.75 + 1，向上取整到 2 的幂。1000 / 0.75 ≈ 1333 → 用 2048。

### 5.4 为什么 key 要用不可变对象

如果 key 放进去之后又改了内容（比如可变对象的字段变了），`hashCode` 变了，就再也找不到它——桶的位置对不上。

**规则**：作为 key 的对象，要么用 `String`、`Integer` 这类不可变类型，要么自己保证放进去之后不改。

## 6. HashMap 常用操作

```java
Map<String, Integer> count = new HashMap<>();

// ① 普通 get + 判空
Integer n = count.get("ems-01");
count.put("ems-01", n == null ? 1 : n + 1);

// ② getOrDefault：没有就给默认值
int m = count.getOrDefault("ems-01", 0) + 1;

// ③ putIfAbsent：不存在才放
count.putIfAbsent("ems-01", 0);

// ④ computeIfAbsent：不存在就计算一个放进去
Map<String, List<String>> byDevice = new HashMap<>();
byDevice.computeIfAbsent("ems-01", k -> new ArrayList<>()).add("record-1");

// ⑤ compute / merge：原子地更新
count.compute("ems-01", (k, v) -> v == null ? 1 : v + 1);
count.merge("ems-01", 1, Integer::sum);        // 计数首选
```

`merge` 是计数最简洁的写法：key 不存在就放 1，存在就把旧值和 1 相加。

| 方法 | 作用 |
| --- | --- |
| `put(k, v)` | 放，返回旧值 |
| `get(k)` | 取，没有返回 null |
| `getOrDefault(k, d)` | 取，没有返回 d |
| `putIfAbsent(k, v)` | k 不存在才放 |
| `computeIfAbsent(k, f)` | k 不存在才计算并放 |
| `compute(k, f)` | 总是计算并放 |
| `merge(k, v, f)` | 合并旧值和新值 |
| `remove(k)` | 删 |
| `replace(k, v)` | 存在才替换 |

## 7. HashMap 遍历与删除

### 7.1 四种遍历

```java
Map<String, Double> map = new HashMap<>();

// ① 遍历键值对（最常用）
for (Map.Entry<String, Double> e : map.entrySet()) {
    System.out.println(e.getKey() + " = " + e.getValue());
}

// ② 遍历键
for (String key : map.keySet()) {
    System.out.println(key);
}

// ③ 遍历值
for (Double v : map.values()) {
    System.out.println(v);
}

// ④ forEach（JDK 8+）
map.forEach((k, v) -> System.out.println(k + " = " + v));
```

### 7.2 遍历时删除

**错误写法**（会抛 `ConcurrentModificationException`）：

```java
for (String key : map.keySet()) {
    if (key.startsWith("ems")) {
        map.remove(key);        // 抛异常！
    }
}
```

三种正确写法：

```java
// ① Iterator
Iterator<Map.Entry<String, Double>> it = map.entrySet().iterator();
while (it.hasNext()) {
    Map.Entry<String, Double> e = it.next();
    if (e.getKey().startsWith("ems")) {
        it.remove();
    }
}

// ② removeIf（JDK 8+，只适用于 keySet/values/entrySet 的视图）
map.entrySet().removeIf(e -> e.getKey().startsWith("ems"));

// ③ 先收集要删的 key，再统一删
List<String> toRemove = new ArrayList<>();
for (String key : map.keySet()) {
    if (key.startsWith("ems")) {
        toRemove.add(key);
    }
}
toRemove.forEach(map::remove);
```

### 7.3 排序

```java
// 按 key 排序
List<String> keys = new ArrayList<>(map.keySet());
Collections.sort(keys);

// 按 value 排序（Top N 常用）
List<Map.Entry<String, Double>> entries = new ArrayList<>(map.entrySet());
entries.sort((a, b) -> Double.compare(b.getValue(), a.getValue()));   // 降序
```

## 8. HashSet 与去重

### 8.1 HashSet 底层

`HashSet` 内部就是一个 `HashMap`，元素当 key，value 是一个固定的占位对象：

```java
// 简化版源码
public class HashSet<E> {
    private HashMap<E, Object> map = new HashMap<>();
    private static final Object PRESENT = new Object();

    public boolean add(E e) {
        return map.put(e, PRESENT) == null;   // 放成功返回 true
    }
}
```

所以：**HashSet 的去重能力来自 HashMap 的 key 唯一性**。

### 8.2 去重原理

```java
Set<String> set = new HashSet<>();
set.add("A");      // 新元素，size=1
set.add("A");      // hashCode 相同、equals 相等，加不进去
```

判断步骤：

1. 算 `hashCode`，找到桶；
2. 桶里有元素，逐个用 `equals` 比较；
3. 有相等的就认为重复，不加。

### 8.3 自定义对象去重

必须**同时重写 `equals` 和 `hashCode`**，否则会「去重失败」：

```java
public class Device {
    private String id;
    private String name;

    // 只重写 equals 不重写 hashCode：两个内容相同的对象 hashCode 不同，
    // 会落到不同的桶里，HashSet 认为它们是两个不同的元素。
}
```

正确写法：

```java
public class Device {
    private final String id;
    private final String name;

    public Device(String id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) {
            return true;
        }
        if (o == null || getClass() != o.getClass()) {
            return false;
        }
        Device other = (Device) o;
        return Objects.equals(id, other.id) && Objects.equals(name, other.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, name);
    }
}
```

用 IDEA 的 **Alt + Insert → equals() and hashCode()** 一键生成，比自己写靠谱。

## 9. Hashtable：老式线程安全 Map

`Hashtable` 是 JDK 1.0 就有的类，也是哈希表，但有几个特点：

```java
Hashtable<String, Double> table = new Hashtable<>();
table.put("ems-01", 26.4);
table.get("ems-01");
table.elements();              // Enumeration，老式遍历
```

### 9.1 和 HashMap 的区别

| | HashMap | Hashtable |
| --- | --- | --- |
| 出生 | JDK 1.2 | JDK 1.0 |
| 线程安全 | 否 | 是（每个方法都 `synchronized`） |
| null 键 | 允许 1 个 | **不允许**，抛 `NullPointerException` |
| null 值 | 允许 | **不允许** |
| 性能 | 快 | 慢（全表锁） |
| 遍历 | `Iterator` | `Iterator` / `Enumeration` |
| 推荐 | 日常使用 | 只在老代码里遇到 |

### 9.2 为什么不推荐

```java
Hashtable<String, Double> table = new Hashtable<>();
table.put("ems-01", null);       // NullPointerException！
```

即使单线程，`Hashtable` 也把每个操作加锁，性能比 `HashMap` 差。

**替代方案**：

| 场景 | 用什么 |
| --- | --- |
| 单线程 | `HashMap` |
| 多线程 | `ConcurrentHashMap` |
| 需要包一层同步 | `Collections.synchronizedMap(new HashMap<>())` |

> 注意：类名是 `Hashtable`（t 小写），不是 `HashTable`。写错会编译不过。

## 10. LinkedHashMap 与 LRU 缓存

`LinkedHashMap` 在 HashMap 基础上多了一条双向链表，能保持顺序。

```java
Map<String, Double> map = new LinkedHashMap<>();
map.put("b", 2.0);
map.put("a", 1.0);
map.put("c", 3.0);
// 遍历顺序：b, a, c（插入顺序）
```

构造时传 `accessOrder = true`，就变成「最近访问的排到最后」，可以拿来做 LRU 缓存：

```java
public class LruCache<K, V> extends LinkedHashMap<K, V> {
    private final int maxSize;

    public LruCache(int maxSize) {
        super(16, 0.75f, true);       // true = 按访问顺序
        this.maxSize = maxSize;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > maxSize;      // 超过上限就删最老的
    }
}
```

```java
LruCache<String, Double> cache = new LruCache<>(3);
cache.put("a", 1.0);
cache.put("b", 2.0);
cache.put("c", 3.0);
cache.get("a");          // 访问 a，a 变成最新的
cache.put("d", 4.0);     // 超了，删掉最久没用的 b
```

注意：这个 LRU 缓存**不是线程安全**的，多线程要自己加锁或换 `ConcurrentHashMap` + 手写淘汰。

## 11. TreeMap 与 TreeSet

按 key 排序的 Map：

```java
Map<String, Double> map = new TreeMap<>();
map.put("c", 3.0);
map.put("a", 1.0);
map.put("b", 2.0);
// 遍历顺序：a, b, c

map.firstKey();              // "a"
map.lastKey();               // "c"
map.headMap("b");            // {"a":1.0}
map.tailMap("b");            // {"b":2.0,"c":3.0}
map.subMap("a", "c");        // {"a":1.0,"b":2.0}
```

自定义排序：

```java
Map<String, Double> map = new TreeMap<>(Comparator.reverseOrder());
// 或者按长度排序
Map<String, Double> byLength = new TreeMap<>(Comparator.comparingInt(String::length));
```

TreeSet 类似：

```java
Set<Integer> set = new TreeSet<>(Comparator.reverseOrder());
set.add(1);
set.add(3);
set.add(2);
// 遍历：3, 2, 1
```

要点：

- key 必须可比较（实现 `Comparable`）或提供 `Comparator`，否则抛 `ClassCastException`；
- 不允许 null key；
- 性能 O(log n)，比 HashMap 慢，但能排序、能按范围查。

## 12. equals 与 hashCode

### 12.1 约定

| 规则 | 说明 |
| --- | --- |
| `equals` 相等 → `hashCode` 必须相等 | 否则 HashSet/HashMap 会重复 |
| `hashCode` 相等 → `equals` 不一定相等 | 叫哈希冲突，正常现象 |
| 重写 `equals` 必须重写 `hashCode` | 标准要求 |
| 用于 key 的对象要不可变 | 否则放进去后找不到 |

### 12.2 例子：为什么必须一起重写

```java
public class Point {
    int x;
    int y;

    @Override
    public boolean equals(Object o) {
        return o instanceof Point p && p.x == x && p.y == y;
    }
    // 没重写 hashCode：默认用地址，两个 x、y 相同的对象 hashCode 不同
}

Set<Point> set = new HashSet<>();
set.add(new Point(1, 2));
set.add(new Point(1, 2));     // 内容相同，但 hashCode 不同，被当成两个元素
System.out.println(set.size());   // 2，去重失败
```

重写 `hashCode` 之后才是 1。

### 12.3 生成的写法

```java
@Override
public int hashCode() {
    return Objects.hash(x, y);      // JDK 7+，简单可靠
}

// 或者手写（性能略好）
@Override
public int hashCode() {
    int result = Integer.hashCode(x);
    result = 31 * result + Integer.hashCode(y);
    return result;
}
```

## 13. 并发集合

多线程同时读写普通 `HashMap` / `ArrayList`，轻则丢数据，重则死循环（JDK 7 的 HashMap），一定要换并发容器或加锁。

### 13.1 为什么普通集合不行

```java
// 两个线程同时 add，可能丢数据
List<String> list = new ArrayList<>();

// 两个线程同时 put，可能覆盖、size 错乱；JDK 7 的 HashMap 甚至可能死循环
Map<String, Double> map = new HashMap<>();
```

三种解决办法：

| 办法 | 说明 |
| --- | --- |
| 换并发集合 | `ConcurrentHashMap`、`CopyOnWriteArrayList`（推荐） |
| 加锁 | `synchronized` 包住所有读写（简单但慢） |
| 不共享 | 每个线程自己一份数据，最后合并（最快但要多写代码） |

### 13.2 ConcurrentHashMap 是怎么做到的

| 版本 | 做法 | 锁粒度 |
| --- | --- | --- |
| JDK 7 | 分段锁 `Segment`（默认 16 段） | 一段 |
| JDK 8+ | `CAS` + `synchronized` 锁**桶的头节点** | 一个桶 |

JDK 8 的关键点：

- 数组（桶）用 `volatile` 修饰，**读操作基本不加锁**；
- 写的时候只锁「要改的那个桶」，其他桶照样能读写；
- 扩容时多个线程可以一起帮忙迁移数据（transfer）；
- 链表长度 ≥ 8 且数组 ≥ 64 时转红黑树。

结果：读几乎无锁，写只影响一个桶，并发度远高于 `Hashtable`（全表锁）。

### 13.3 常用操作

普通操作：

```java
ConcurrentHashMap<String, Double> map = new ConcurrentHashMap<>();

map.put("ems-01", 26.4);          // 放
map.get("ems-01");                // 26.4
map.getOrDefault("ems-99", 0.0);  // 0.0
map.remove("ems-01");             // 删
map.containsKey("ems-01");
map.size();                       // 估算值
```

**原子复合操作**（重点）：先查再改不是原子的，两个线程可能同时改。

```java
// 错：先查再改，中间可能被别的线程插入
if (!map.containsKey("ems-01")) {
    map.put("ems-01", 0.0);
}

// 对：用原子方法
map.putIfAbsent("ems-01", 0.0);                       // 不存在才放
map.computeIfAbsent("ems-01", k -> 0.0);              // 不存在才计算
map.compute("ems-01", (k, v) -> v == null ? 1.0 : v + 1);
map.merge("ems-01", 1.0, Double::sum);                // 计数首选
map.replace("ems-01", 27.0);                          // 存在才替换
```

| 方法 | 原子性 | 用途 |
| --- | --- | --- |
| `putIfAbsent(k, v)` | 是 | 只在不存在时放 |
| `computeIfAbsent(k, f)` | 是 | 只在不存在时计算并放 |
| `compute(k, f)` | 是 | 总是计算并放 |
| `merge(k, v, f)` | 是 | 合并旧值，计数 |
| `replace(k, v)` | 是 | 存在才替换 |
| `remove(k, v)` | 是 | 值匹配才删 |

### 13.4 遍历、size 与弱一致性

```java
// 遍历：弱一致性迭代器，不会抛 ConcurrentModificationException
for (Map.Entry<String, Double> e : map.entrySet()) {
    System.out.println(e.getKey() + " = " + e.getValue());
}

// 遍历中删除是安全的
map.entrySet().removeIf(e -> e.getValue() < 0);

// forEach
map.forEach((k, v) -> System.out.println(k + " -> " + v));
```

三个「不精确」要知道：

| 行为 | 说明 |
| --- | --- |
| `size()` | 并发下是**估算值**，可能不准 |
| `mappingCount()` | 返回 long，比 size 适合大集合，但仍不精确 |
| 遍历 | 弱一致：可能看不到最新写入，也可能看到部分更新，但**不会**抛异常 |

如果需要「精确的某一时刻快照」，自己加锁或用 `new HashMap<>(map)` 复制一份再遍历。

### 13.5 CopyOnWriteArrayList

原理：**每次写都复制整个数组**，读的时候读的是旧数组，所以读不加锁、迭代器是快照。

```java
CopyOnWriteArrayList<String> devices = new CopyOnWriteArrayList<>();
devices.add("ems-01");
devices.remove("ems-01");

for (String d : devices) {
    System.out.println(d);      // 迭代器是快照，遍历时增删不影响它
}
```

| 特点 | 说明 |
| --- | --- |
| 读 | 快，不加锁 |
| 写 | 慢，每次复制整个数组（O(n)） |
| 内存 | 写的那一刻要两份数组 |
| 适合 | 读多写少：监听器列表、设备列表、配置项 |
| 不适合 | 频繁写、几万个元素 |

### 13.6 并发队列

**ConcurrentLinkedQueue**：无锁队列，适合高并发入队出队。

```java
ConcurrentLinkedQueue<String> queue = new ConcurrentLinkedQueue<>();
queue.offer("a");
queue.poll();          // 取并删，空返回 null
queue.peek();          // 只看不删
```

注意：`size()` 要遍历整个队列，O(n)，**别在大队列上频繁调**。

**BlockingQueue**：队列满了/空了会等待，是生产者消费者模型的标准工具。

| 实现 | 特点 | 场景 |
| --- | --- | --- |
| `ArrayBlockingQueue(n)` | 有界数组队列 | 固定容量缓冲 |
| `LinkedBlockingQueue(n)` | 可选有界链表队列 | 吞吐高 |
| `PriorityBlockingQueue` | 按优先级出队 | 任务调度 |
| `SynchronousQueue` | 不存储，必须直接交给消费者 | 线程池 handing-off |
| `DelayQueue` | 延迟到期才能取 | 定时任务、缓存过期 |

```java
BlockingQueue<String> queue = new ArrayBlockingQueue<>(100);

// 生产者
queue.put("data");              // 满了阻塞
queue.offer("data");            // 满了返回 false
queue.offer("data", 1, TimeUnit.SECONDS);   // 等 1 秒

// 消费者
String item = queue.take();     // 空了阻塞
String item2 = queue.poll(1, TimeUnit.SECONDS);  // 等 1 秒，超时返回 null
```

### 13.7 有序的并发集合

`ConcurrentSkipListMap` / `ConcurrentSkipListSet`：基于跳表，**有序 + 并发安全**，可以替代 `TreeMap` 在并发场景使用。

```java
ConcurrentSkipListMap<String, Double> map = new ConcurrentSkipListMap<>();
map.put("ems-02", 27.0);
map.put("ems-01", 26.4);

map.firstKey();          // "ems-01"，有序
map.lastKey();           // "ems-02"
map.headMap("ems-02");   // 小于 "ems-02" 的部分
```

性能比 `ConcurrentHashMap` 稍差（O(log n)），但能排序、能范围查询。

### 13.8 实战：五个常见场景

**场景一：在线设备表**

```java
ConcurrentHashMap<String, Device> online = new ConcurrentHashMap<>();

online.put(deviceId, device);                    // 上线
online.remove(deviceId);                         // 下线
boolean onlineNow = online.containsKey(deviceId);
int count = online.size();

// 原子地「没有就新建」
Device d = online.computeIfAbsent(deviceId, id -> new Device(id));
```

**场景二：计数器**

```java
ConcurrentHashMap<String, Integer> count = new ConcurrentHashMap<>();
count.merge(deviceId, 1, Integer::sum);          // 每个设备上报次数 +1
```

如果只是单纯计数、不需要按 key，用 `LongAdder` 更快：

```java
LongAdder total = new LongAdder();
total.increment();
long v = total.sum();
```

**场景三：本地缓存**

```java
ConcurrentHashMap<String, CachedValue> cache = new ConcurrentHashMap<>();

CachedValue get(String key) {
    return cache.computeIfAbsent(key, k -> loadFromDb(k));
}

// 简单的过期清理
cache.entrySet().removeIf(e -> e.getValue().isExpired());
```

**场景四：广播给所有监听者**

```java
CopyOnWriteArrayList<Listener> listeners = new CopyOnWriteArrayList<>();

listeners.add(listener);
listeners.remove(listener);

for (Listener l : listeners) {      // 遍历快照，增删安全
    l.onEvent(event);
}
```

**场景五：生产者消费者**

```java
BlockingQueue<Task> queue = new ArrayBlockingQueue<>(500);

// 消费者
new Thread(() -> {
    while (true) {
        try {
            Task task = queue.take();
            handle(task);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            break;
        }
    }
}).start();

// 生产者
queue.put(task);
```

### 13.9 选型表

| 需求 | 用什么 | 备注 |
| --- | --- | --- |
| 并发 Map | `ConcurrentHashMap` | 不允许 null |
| 并发 Set | `ConcurrentHashMap.newKeySet()` | |
| 有序并发 Map | `ConcurrentSkipListMap` | O(log n) |
| 读多写少 List | `CopyOnWriteArrayList` | 写会复制整个数组 |
| 高并发队列 | `ConcurrentLinkedQueue` | size 是 O(n) |
| 生产者消费者 | `ArrayBlockingQueue` / `LinkedBlockingQueue` | 有界更安全 |
| 延迟任务 | `DelayQueue` | |
| 已有集合要加锁 | `Collections.synchronizedMap(new HashMap<>())` | 全表锁，慢 |

### 13.10 常见坑

| 坑 | 现象 | 解决 |
| --- | --- | --- |
| 把 `ConcurrentHashMap` 当普通 Map 用「先查再改」 | 并发下丢更新 | 用 `compute`/`merge`/`putIfAbsent` |
| 往 CHM 里放 null | `NullPointerException` | 用 `getOrDefault`、`Optional` |
| 以为 `size()` 精确 | 计数偶尔不对 | 用 `mappingCount` 或自己维护 `LongAdder` |
| 遍历时依赖最新数据 | 读不到刚写入的 | 弱一致性，需要精确就复制一份 |
| 用 `CopyOnWriteArrayList` 存频繁写的数据 | 卡顿、内存涨 | 换 `ArrayList` + 锁，或 `ConcurrentLinkedQueue` |
| 在 CHM 上 `synchronized(map)` 做复合操作 | 锁不住内部桶 | 用原子方法，别自己加锁 |
| `ConcurrentLinkedQueue.size()` 频繁调用 | 变慢 | 只在必要时调，或用计数器 |
| `Hashtable` 当并发容器 | 性能差 | 换 `ConcurrentHashMap` |
| 多线程共享普通 `ArrayList` | 丢数据、`ArrayIndexOutOfBoundsException` | 换并发容器或加锁 |
| 以为并发集合能替代事务 | 多个操作组合仍不原子 | 组合操作用锁或单线程化 |

## 14. 性能对比与选择

### 14.1 时间复杂度

| 操作 | ArrayList | LinkedList | HashSet | HashMap | TreeMap |
| --- | --- | --- | --- | --- | --- |
| 按下标访问 | O(1) | O(n) | — | — | — |
| 按 key 查 | — | — | O(1) 平均 | O(1) 平均 | O(log n) |
| 插入 | O(n) | O(1) 头尾 | O(1) | O(1) | O(log n) |
| 删除 | O(n) | O(1) 头尾 | O(1) | O(1) | O(log n) |
| 遍历 | O(n) | O(n) | O(n) | O(n) | O(n) |

### 14.2 内存

| 结构 | 额外开销 |
| --- | --- |
| `ArrayList` | 数组 + 空槽（扩容留余量） |
| `LinkedList` | 每个元素两个引用（前后指针） |
| `HashMap` | 桶数组 + 每个 Entry 对象 |
| `TreeMap` | 每个节点多存颜色、左右指针 |

### 14.3 选择口诀

- **要顺序、要下标** → `ArrayList`；
- **要去重** → `HashSet`；
- **要键值对** → `HashMap`；
- **要排序** → `TreeMap` / `TreeSet`；
- **要插入顺序** → `LinkedHashMap` / `LinkedHashSet`；
- **要并发** → `ConcurrentHashMap`；
- **老代码里的 `Hashtable` / `Vector`** → 理解、别新增。

## 15. 泛型与类型安全

```java
// 好：指定类型，取出来不用强转
List<String> names = new ArrayList<>();
names.add("A");
String s = names.get(0);

// 差：不指定类型，什么都能放，取出来要强转
List list = new ArrayList();
list.add("A");
list.add(123);
String x = (String) list.get(1);    // ClassCastException
```

Map 同理：

```java
Map<String, List<Double>> data = new HashMap<>();
data.computeIfAbsent("ems-01", k -> new ArrayList<>()).add(26.4);
```

注意：泛型只存在于编译期，运行时会被擦除（所以 `new TypeToken<List<X>>(){}.getType()` 这种技巧才存在）。

## 18. 常见坑

| 坑 | 现象 | 原因与解决 |
| --- | --- | --- |
| 遍历时 `map.remove` | `ConcurrentModificationException` | 用 `Iterator.remove` 或 `removeIf` |
| 自定义对象去重失败 | Set 里出现「重复」元素 | 重写 `equals` 和 `hashCode` |
| 改了 key 的内容 | 再也 get 不到 | key 用不可变对象 |
| `Hashtable` 放 null | `NullPointerException` | 换 `HashMap` 或 `ConcurrentHashMap` |
| `ConcurrentHashMap` 放 null | `NullPointerException` | 用 `getOrDefault` 等 |
| 用 `Hashtable` 当并发容器 | 性能差 | 换 `ConcurrentHashMap` |
| `HashMap` 初始容量太小 | 频繁扩容 | 预估元素数，给容量 |
| `ArrayList` 中间插删多 | 慢 | 用 `LinkedList` 或换数据结构 |
| `Arrays.asList` 上 `add` | `UnsupportedOperationException` | 包一层 `new ArrayList<>(...)` |
| `List.of` 上 `add` | 同上 | 用可变集合 |
| 用 `==` 比较 key | 找不到 | 用 `equals`（Map 内部就是 equals） |
| 多线程共用 `HashMap` | 数据错乱 | 用 `ConcurrentHashMap` |
| `TreeMap` 的 key 不可比较 | `ClassCastException` | 实现 `Comparable` 或传 `Comparator` |

## 19. 老式集合类（Legacy）

JDK 1.0 / 1.1 就存在的老集合，现在还在 `java.util` 里，旧教材、老代码里经常出现，遇到要认识。

### 19.1 老集合清单

| 类 | 类型 | 现在还用吗 | 替代 |
| --- | --- | --- | --- |
| `Vector` | List | 不用 | `ArrayList` |
| `Stack` | 栈 | 不用 | `ArrayDeque` |
| `Hashtable` | Map | 不用 | `HashMap` / `ConcurrentHashMap` |
| `Dictionary` | 抽象类 | 不用 | `Map` 接口 |
| `Properties` | 配置 | **还在用** | 没有替代（配置文件场景） |
| `Enumeration` | 遍历接口 | 不用 | `Iterator` |
| `BitSet` | 位集合 | 偶尔用 | 没有直接替代 |

### 19.2 Vector

```java
Vector<String> v = new Vector<>();
v.addElement("A");          // 老方法，等价 add
v.addElement("B");

v.elementAt(0);             // "A"，等价 get
v.firstElement();           // "A"
v.lastElement();            // "B"
v.removeElement("A");
v.size();

// 老的遍历方式
Enumeration<String> e = v.elements();
while (e.hasMoreElements()) {
    System.out.println(e.nextElement());
}
```

特点：所有方法都 `synchronized`，扩容默认 **2 倍**（可以传 `capacityIncrement` 指定增量）。

`Vector` 的「线程安全」只是把每个方法各自加锁，组合操作照样不安全（比如「先判断再添加」），性能还差。新代码用 `ArrayList`。

### 19.3 Stack

```java
Stack<Integer> stack = new Stack<>();
stack.push(1);          // 压栈
stack.push(2);
stack.peek();           // 2，看栈顶不移除
stack.pop();            // 2，弹出
stack.empty();          // false
stack.search(1);        // 距离栈顶的位置（1 在栈底，返回 2），找不到返回 -1
```

`Stack` 继承 `Vector`，所以也带了一堆 List 方法（比如 `get(0)`），语义混乱。

**替代**：用 `ArrayDeque` 当栈，性能更好：

```java
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1);          // 也可以 addFirst
stack.push(2);
stack.peek();           // 2
stack.pop();            // 2
```

### 19.4 Hashtable 与它的老接口

`Hashtable` 在第 9 章详细讲过，这里补充它的老式遍历：

```java
Hashtable<String, Double> table = new Hashtable<>();
table.put("ems-01", 26.4);

// 老的取键方式，返回 Enumeration
Enumeration<String> keys = table.keys();
while (keys.hasMoreElements()) {
    System.out.println(keys.nextElement());
}

// 老的取值方式
Enumeration<Double> values = table.elements();
```

`Hashtable` 还有一个 `contains(Object value)` 方法，等价于 `containsValue`，名字容易和 `containsKey` 混淆。

### 19.5 Dictionary

`Dictionary` 是 `Hashtable` 的抽象父类，JDK 文档里明确标注 **已过时（obsolete）**：

```java
// 能用，但不要在新代码里写
Dictionary<String, String> d = new Hashtable<>();
d.put("k", "v");
d.get("k");
```

新代码直接用 `Map` 接口 + `HashMap`。

### 19.6 Properties（老类里唯一还常用的）

`Properties` 继承 `Hashtable<Object, Object>`，专门用来读写配置文件（键值都是字符串），本项目 `config.properties` 就是它。

```java
import java.io.Reader;
import java.io.Writer;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.Properties;

// 读
Properties prop = new Properties();
try (Reader reader = Files.newBufferedReader(Path.of("config.properties"), StandardCharsets.UTF_8)) {
    prop.load(reader);
}
String ip = prop.getProperty("db.ip", "127.0.0.1");    // 第二个参数是默认值
String port = prop.getProperty("db.port", "3306");

// 遍历所有键值
for (String name : prop.stringPropertyNames()) {
    System.out.println(name + " = " + prop.getProperty(name));
}

// 写回（整文件覆盖）
prop.setProperty("db.port", "3307");
try (Writer writer = Files.newBufferedWriter(Path.of("config.properties"), StandardCharsets.UTF_8)) {
    prop.store(writer, "Database Configuration");
}
```

要点：

| 要点 | 说明 |
| --- | --- |
| 推荐用 `getProperty` / `setProperty` | 而不是 `get` / `put`，类型更明确 |
| 不允许 null | 底层是 Hashtable，`setProperty(k, null)` 抛 `NullPointerException` |
| `store` 会转义中文 | 存成 `\u4F60` 形式，`load` 能还原，正常现象 |
| `load(Reader)` 用 Reader 的编码 | 用 `Files.newBufferedReader(..., UTF_8)` 避免乱码 |
| `stringPropertyNames()` | 返回所有键的 Set，比 `keySet()` 类型安全 |

本项目 `ConfigManager` 就是「读配置 → 没有就控制台问 → 写盘」的封装，核心就是 `Properties`。

### 19.7 Enumeration

`Enumeration` 是 `Iterator` 之前的老接口，只有两个方法：

```java
Enumeration<String> e = someVector.elements();

while (e.hasMoreElements()) {          // 还有吗
    String s = e.nextElement();        // 取下一个
    System.out.println(s);
}
```

和 `Iterator` 对比：

| | `Enumeration` | `Iterator` |
| --- | --- | --- |
| 方法 | `hasMoreElements` / `nextElement` | `hasNext` / `next` |
| 删除 | 不支持 | `remove()` |
| 支持 for-each | 不支持 | 支持 |
| 状态 | 老接口 | 推荐 |

新代码一律用 `Iterator` 或 for-each，`Enumeration` 只在新老代码对接时出现。

### 19.8 BitSet（位集合）

严格说它不是 `Collection`，但也是 `java.util` 里的老成员，用位来存布尔标记，非常省内存。

```java
import java.util.BitSet;

BitSet bits = new BitSet(64);

bits.set(3);                    // 第 3 位设为 1
bits.set(5);
bits.get(3);                    // true
bits.get(4);                    // false
bits.cardinality();             // 2，1 的个数
bits.nextSetBit(0);             // 3，从 0 开始找第一个 1
bits.nextSetBit(4);             // 5

bits.clear(3);
bits.cardinality();             // 1
```

典型用途：大量「有/没有」的标记（设备在线状态、打卡记录），比 `boolean[]` 省内存。

### 19.9 新旧对照与迁移

| 老写法 | 新写法 | 说明 |
| --- | --- | --- |
| `Vector<String> v = new Vector<>();` | `List<String> l = new ArrayList<>();` | 性能更好 |
| `v.addElement("a")` | `l.add("a")` | 方法名统一 |
| `v.elementAt(0)` | `l.get(0)` | |
| `Stack<Integer> s = new Stack<>();` | `Deque<Integer> s = new ArrayDeque<>();` | 语义更清晰 |
| `Hashtable<K,V>` | `HashMap<K,V>` 或 `ConcurrentHashMap<K,V>` | 并发用 CHM |
| `table.keys()` + `Enumeration` | `map.keySet()` + for-each | |
| `Dictionary<K,V>` | `Map<K,V>` | 抽象类已废弃 |
| `e.hasMoreElements()` | `it.hasNext()` | |
| `e.nextElement()` | `it.next()` | |

迁移示例：

```java
// 旧代码
Vector<String> v = new Vector<>();
v.addElement("A");
Enumeration<String> e = v.elements();
while (e.hasMoreElements()) {
    process(e.nextElement());
}

// 新代码
List<String> list = new ArrayList<>();
list.add("A");
for (String s : list) {
    process(s);
}
```

### 19.10 为什么不要用老类

| 问题 | 说明 |
| --- | --- |
| 同步是「假安全」 | 每个方法各自加锁，组合操作仍不安全，还拖慢速度 |
| API 老旧 | 没有 `computeIfAbsent`、`merge`、Stream 支持 |
| 语义混乱 | `Stack` 继承了 Vector，能 `get(0)` 也能 `push` |
| 文档标记过时 | `Dictionary` 直接标注 obsolete |
| 生态不兼容 | 新库、新框架的参数类型基本都是 `List`/`Map` 接口 |

**例外**：`Properties` 还在大量使用（配置文件就是这么回事），`BitSet` 在需要极致省内存时仍有价值。
